# 固定理赔案例及回归矩阵

全部案例由本地种子数据 `CL001` 到 `CL010` 提供，测试向 `POST /v1/claims/{id}/decide` 发无请求体调用。下面的字段是业务事实，不要求输入 JSON 恰好使用这些字段名。每个案例均应返回一致的 `claim_id` / `policy_number`、三份 `agent_reports`、非空 `reason`、非空且唯一的 `trace_id`；响应可在该案件决策历史找到对应审计记录。仅凭状态码 200 不算通过。

| ID | 种子案件必须表达的事实 | 预期建议 | 回归必须验证 |
| --- | --- | --- | --- |
| CL001 | 材料完整，条款明确承保，审核有效，风险低且无疑点 | `APPROVED` | 引用真实承保条款；三专业报告一致 |
| CL002 | 材料完整，条款明确承保，审核有效，风险中且无重大疑点 | `APPROVED` | 中风险没有被误判高风险；有承保原文 |
| CL003 | 材料完整、风险低，洪水事故被本保单明确排除 | `DENIED` | 引用明确的洪水除外原文，不能仅以搜索无结果拒绝 |
| CL004 | 材料完整，风险低，事故触发保单明列除外责任 | `DENIED` | 原文包含可核对的除外责任，理由指出触发事实 |
| CL005 | 材料完整，车辆机械故障触发保单明确列出的除外责任 | `DENIED` | 与 CL004 触发事实不同；原文和理由能同时核对 |
| CL006 | 维修估价/损失证明等必需材料缺失，其余低风险 | `NEED_MORE_INFO` | 明确列出缺失材料，不因其他报告肯定而批准 |
| CL007 | 必需事故陈述缺失，其余事实不下载改变补件需求 | `NEED_MORE_INFO` | 明确指出缺事故陈述，不得批准 |
| CL008 | 材料完整、条款承保，但风险等级高 | `HUMAN_REVIEW` | 高风险不得批准，保留风险原因和证据 |
| CL009 | 材料完整、条款承保，但出现重大欺诈/事实疑点 | `HUMAN_REVIEW` | 即便量化风险未达 high，也不得批准 |
| CL010 | 材料完整，但保单找不到或条款证据不可核验 | `HUMAN_REVIEW` | `covered=null` 或等价未知态，不能当作明确不承保而拒绝，更不能批准 |

`CL003`、`CL004`、`CL005` 需有实际可引用的 Markdown 条款；若没有对应条款，应修复种子数据，而不是制造引文。`CL005` 与 `CL004` 使用不同事故触发同类规则，不能只修改 ID 和理由。任何无法证实的无效索赔嫌疑或材料矛盾应为 `HUMAN_REVIEW`，不能为满足表格编造否定证据。

另外至少覆盖这些非案例路径：未知 ID 返回 404；`GET /health` 正常；列表和详情能检索十案；重复决策生成可追查的多条历史而不覆盖旧记录；缺条款与明确除外条款有不同结论；在构造“缺必需材料且高风险”时验证缺材料优先；模拟模型/数据失败绝不自动批准。
